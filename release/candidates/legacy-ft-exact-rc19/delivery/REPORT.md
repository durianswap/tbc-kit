# 旧 FT 定向修复候选验收

JS：`0.1.0-rc.19`；Native：`0.1.0-rc.19.native.2`。

## 修复范围

- 旧 FT 审批摘要补齐经过认证的合约 ID；缺失、替换后重新计算计划哈希的负例仍被校验拒绝。
- 指定输入贯穿读取、规划、审批绑定和 finalize。指定的原始 FT 与手续费输入必须各消费一次，不静默补选外部输入；需要时复用合并和手续费归集依赖。
- 自动选币路径的交易字节、费用输出和待签摘要与 rc.18 对照一致；新增摘要字段会改变计划哈希，未批准的旧计划应重新准备。

## 已执行

- Rust 定向 8 项；相邻 NFT/旧稳定币/TBC20 28 项及 Coin 7 项通过。
- JS 源码与 RN 模板 15 项、公共映射/取数回归 25 项、最终安装包 9 项通过。
- Swift 与 Kotlin/JNI 独立接入通过；iOS 模拟器与 Android ART 各 71 条原生方法向量通过（含 18 条本次拒绝向量），并发 16 条检查通过。
- 最终 JS 干净安装、公开导出、类型声明、ESM/CJS、浏览器与 RN 入口检查通过。两平台 Native 归档独立解压、模板同步及哈希配套检查通过。
- Host 定向流程每批批准一次；拒绝不签名。既有材料与父交易复用，HTTP 请求计数检查未增加额外下载。

## 验收边界

本轮没有真实节点广播、未重发成功交易，也未操作真实私钥。原生运行时回放使用合成材料，不冒充真实链验收或真机钱包 UI 验收。已有未修改的 31/500 输入压力测试重跑被中止，不计为通过。独立旧 FT merge 仍限 2–5 个资产输入，其余输入数、交易数和费用政策未放宽。

当前交付及受保护资源共 1362 个文件（含合作方 174 个文件）哈希保持不变；签名算法未修改。本候选仅本地交付，未发布、未推送，也没有替换 Flutter 合作方包。
