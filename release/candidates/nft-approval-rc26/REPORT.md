# rc.26 定向修复与双端速度报告

日期：2026-11-02（Asia/Shanghai；原始证据使用 UTC）。

## 结论与边界

审批等待期间到期、Native fence 拒绝后返回 `-32603` 的问题已修复。
iOS 与 Android 的真实 DApp → Provider → 钱包 → 原生审批路径均返回
`stopped / expired`，各一次审批展示、零签名、零广播。

Android 批量铸造的主要本地瓶颈是独立验收钱包的私有 Hermes VM 未接入
已有原生 SHA-256 后端；Core 的绑定摘要因而走可移植 JS 实现。
接通原有原生接口后，同设备、同材料、同校验和签名次数的 11 NFT 本地
任务中位数从 **14,290.86ms 降至 1,710.88ms（减少 88.03%）**。

这是候选验收，不是“所有场景零 bug”证明。速度数据来自模拟器、本地
合成材料和公开测试签名器，不包含真实 API 等待、人工批准等待、网络广播
或区块确认。当前合作方交付包与当前发布版不变；本轮没有发送新交易。

## 1. 修复位置与原因

- `source/packages/kit/src/nft-mint-job-wallet.ts`：原生审批 Promise 拒绝时，
  原实现跳过了 UI 返回后的可信时钟刷新。改为在 `finally` 刷新；成功路径
  原有的一次刷新仍是一次，不增加 HTTP 请求。
- `source/packages/kit/src/nft-mint-job.ts`：只捕获审批适配器的拒绝，按刷新
  后的可信时间/取消状态返回明确终态。尚未到期的真实适配器错误仍报错；
  已返回的审批材料在 catch 外做原有解析与绑定检查，篡改材料不会被包装成
  正常到期。没有根据错误字符串猜测授权，也没有改写票据或延长期限。
- 新增 `nft-job-approval-failure.test.mjs`，并补充审批到期及私有运行时接入文档。
- Android 验收钱包复用了原有 `sha256-jsi.hpp` 和 `native-sha256.mjs`，
  通过 Android `MessageDigest("SHA-256")` 计算同一字节视图的摘要。
  保留启动向量、自检、offset/length 边界及所有绑定校验。不缓存可变摘要，
  不修改签名算法、Engine、Native ABI 或 WASM。

Android 的提速需要钱包原生运行时接入该已有接口并重建 App；单独更新 npm
包不会自动安装原生 hook。接入代码和文档随源码快照提供。它不是新增 DApp
方法，也不应暴露给网页。没有采纳其他 ASCII/字节码实验来叠加此次收益。

101 项任务每端均：一次整批审批、11 个内部 Core 工作批次、202 次测试签名、
101 个不同的合成交易结果。最初材料读取为索引一次、手续费 UTXO 一次；
raw/decoded/status/reconcile 均为零（父交易已预置缓存）。没有因内部工作
批次增加材料下载。

双端真实 UI 到期复验使用真实 API 只读预取，各 3 次 GET：集合槽位索引、
手续费 UTXO、集合父交易；并行发起，无重复下载。使用原专用验收账户，
请求在原始 30 秒期限后点击批准，原生 fence 拒绝；不是通过加长超时过关。

部分成功定向用例在合成提交接受前两笔后到期，返回 `partial / expired`，
保留两笔原 txid，未提交后续交易、不重发已接受项。这是受控提交模拟，
不是新一次链上广播。

## 3. 同口径本地速度

计时范围：公开业务调用开始到任务结果返回，包含本地材料处理、Core/Host、
Native Engine 和公开测试签名计算；排除测试 harness 创建、App 启动、真实
网络、用户等待。开启了相同的分段诊断插桩，因此不要把它当真机 SLA。

### Android：11 个 NFT，三次相同任务

| 轮次 | rc.25 / JS SHA | rc.26 / 原生 SHA |
| --- | ---: | ---: |
| 1 | 15,462.84ms | 2,720.16ms |
| 2 | 14,290.86ms | 1,710.88ms |
| 3 | 14,282.14ms | 1,695.21ms |
| 中位数 | **14,290.86ms** | **1,710.88ms** |

第二轮 SHA 自身耗时从 **12,776.48ms → 46.46ms**，摘要调用仍为 1,257 次。
每轮均为一次审批、22 次签名、2 次 policy 调用、8 次账户读取、相同的两次
材料读取。`hashCanonical` 683、Schema 检查 1,332、checkpoint 创建 122、
checkpoint 验证 459 次均不变。没有靠删除验证获得提速。

### iOS：11 个 NFT，六次采样

- rc.25：684、361、335、751、362、313ms；中位数 **361.5ms**。
- rc.26：774、401、309、665、386、321ms；中位数 **393.5ms**。
- 本次样本中位差 **+32ms（+8.85%）**。冷热样本有波动：新包既有比旧包
  快的轮次，也有慢的轮次。不能据此宣称“已证明零性能回归”，也不能把它
  当作稳定的固定开销。成功路径没有新增取数、签名、摘要或绑定检查次数；
  本轮重点 Android 瓶颈已消除，iOS 不作过度性能保证。

| --- | ---: | --- |

## 4. 证据解释与不重复广播

- 原 rc.25 的 44 笔测试网交易在 `2026-11-01T15:13:16.819Z`、高度 839503
  已至少 1 次确认，原文与 journal 一致，独立脚本 VM 通过。本轮保留原
  `prior-rc25-chain-reconciliation.json`，不将其改写为 rc.26 新广播结果。
- 本轮再次只读比较两个专用 App 的 journal：22/22 条分别与原记录完全
  相同。到期 UI 测试也有签名/POST 禁止护栏；记录显示未触及这些护栏。
- 测速样本 bindingHash 随会话 `createdAt` 变化，这是上下文绑定的一部分。
  独立固定同一创建时间后，新旧包完整绑定相同；交易本身的输入/输出结果
  也相同。没有为了比较而修改产品时间规则。
- 实际 UI 壳保留旧 `rc.25` 标签与通用 `outcome: signed`（Promise fulfilled）
  诊断字段；它们不是已签名的证据。rc.26 JS 哈希已单独记录，公开业务结果
  是 `stopped/expired`，实际 `signer.sign=0`。判断以公开结果和调用计数为准。

## 6. 仍需诚实保留的限制

本轮为已修复边界的定向复验，未重复全部功能、未新发真实 NFT、不提供
真机温度/后台调度/弱网的性能保证。iOS 小幅样本差异尚不足以判为稳定回归
或彻底排除回归。其它钱包必须接入正确的私有摘要后端才会获得 Android
这项收益，不能仅看 npm 版本号推断原生集成已经生效。
